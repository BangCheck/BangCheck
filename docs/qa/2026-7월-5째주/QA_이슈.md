## ⚠️ 먼저 볼 것 — 5건 중 3건이 5월 기록에 이미 있다

5월 4째주 QA와 대조한 결과다. 그때 **전부 "개발완료 ✅"로 표시됐고 "확인 여부"는 전부 ❌**였다.
개발은 끝났다고 적혔지만 아무도 확인하지 않았고, 두 달 뒤 같은 항목이 다시 올라왔다.

| 3 방카드 위치 아이콘 | "방카드에 위치 아이콘 추가 — 클릭 시 지도 마커로 이동" | 개발완료 ✅ / 확인 ❌ | **판정 불가** |

### 2-3은 두 번째다 (세 번이 아니다)

GitHub 이력을 확인했다:
- #207 `[bug] POST /checklist/items/custom — 409 Data integrity violation으로 나만의 항목 추가 불가` — 2026-05-28T07:05:24Z, CLOSED
- #208 — **제목이 #207과 완전히 동일하고 생성 시각이 16초 뒤(07:05:40Z)다. 같은 보고의 중복 등록이지 별개 회차가 아니다.**
- #209 `fix: custom 항목 추가 시 409 오류 수정` — 2026-05-28T10:00:55Z, **MERGED**

실제 이력은 **5월 28일 QA 보고 → 이슈 등록(중복 2건) → #209 머지 → 7월 29일 재보고**다.
즉 **같은 증상이 두 번 보고됐고, 그 사이에 한 번 고쳤다고 기록됐다.**
(5월 QA 기록의 "개발완료 ✅"와 #209는 같은 날짜대라 같은 수정으로 보인다.
 별개의 두 번째 수정이었다는 근거는 없다.)

원인이 다르거나, 고친 것이 배포되지 않았거나, 회귀했다.
이번에는 재현 조건과 실패 응답을 먼저 확정하고 고친다.

### 3(방카드 위치 아이콘)은 재발인지 아닌지 판정할 수 없다

5월 기록이 **개발완료 ✅ / 확인 ❌**다. 즉 개발됐다고 적혔을 뿐 배포·검증된 적이 없다.
그러면 지금 아이콘이 안 보이는 것이 **회귀인지 애초에 반영되지 않은 것인지 구분할 근거가 없다.**
"재발"로 세면 없는 이력을 있는 것처럼 집계하게 되므로 여기서는 판정을 보류한다.
판정하려면 5월 이후 이 기능이 실제 배포된 적이 있는지(머지된 PR·릴리스)를 먼저 확인해야 한다.

### 2-1은 회귀가 아니라 요구가 뒤집힌 것이다

- 5월: 유형 선택 시 **기본 + 유형** 항목을 같이 제공 → 그렇게 개발함
- 7월: 유형 선택 시 **유형 항목만** 노출 (예: 벌레 회피형 → 창문/방충망, 현관/문틈, 벌레 흔적, 하수구/곰팡이 냄새)

지금 화면이 기본 항목을 같이 보여주는 것은 **5월 요구를 구현한 결과**다. 버그가 아니다.
고치기 전에 어느 쪽이 확정 사양인지 정해야 한다. 정하지 않고 고치면 다음 QA에서 또 뒤집힌다.
