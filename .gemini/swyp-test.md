# /swyp-test — 테스트 시나리오 관리

이슈의 테스트 케이스를 관리하고 전체 테스트 현황을 추적합니다.

---

## 사전 점검

1. `gh auth status` — 미인증이면 중단
2. `git remote get-url origin` — repo 확인

---

## 케이스 선택

```
SWYP 테스트 관리

1. [status]  전체 테스트 현황
2. [view]    특정 페이지/이슈 테스트 상세
3. [add]     이슈에 테스트 케이스 추가
4. [report]  마일스톤별 테스트 리포트
```

---

## status — 전체 테스트 현황

```bash
gh issue list --repo {repo} --label "page" --state all --json number,title,body,state --limit 50
```

각 page 이슈 body에서 "## 테스트 케이스" 섹션 파싱:
- `- [x]` → 통과 (✅)
- `- [ ]` → 미확인 (❌)

출력:

```
SWYP 테스트 현황 — {날짜}

## 전체 요약
| 전체 | 통과 | 미확인 | 진행률 |
|------|------|--------|-------|
| {n} | {n} | {n} | {%} |

## 페이지별 상세

### [page] 로그인 페이지 (#10) — 67% (6/9)

  정상 동작:
    ✅ 이메일/비밀번호 입력 후 로그인 성공
    ✅ 카카오 소셜 로그인 성공
    ✅ 로그인 후 메인 페이지로 이동

  예외 처리:
    ✅ 잘못된 비밀번호 → 에러 메시지
    ❌ 네트워크 오류 → 재시도 안내
    ✅ 빈 필드 제출 → 유효성 검사

  UI/UX:
    ✅ 모바일 반응형 정상
    ❌ 로딩 스피너
    ❌ 비밀번호 show/hide
```

경고: 테스트 섹션 없는 page, closed인데 미통과 있음, 진행률 50% 미만

---

## view — 특정 이슈 테스트 상세

```bash
gh issue view {number} --repo {repo} --json number,title,body,labels
```

page 이슈면 하위 task들의 테스트도 수집:

```
[page] 로그인 페이지 (#10) — 테스트 상세

## 페이지 테스트 (6/9)
  ✅ / ❌ 항목 나열

## task별 테스트
  #11 로그인 폼 UI (3/3) ✅
  #12 카카오 소셜 로그인 (1/3) ⚠
```

---

## add — 테스트 케이스 추가

기존 테스트 섹션에 추가하거나, 없으면 새로 생성합니다.

페이지 유형별 자동 추천:

| 유형 | 추천 카테고리 |
|------|-------------|
| 폼 | 정상 제출, 유효성 검사, 서버 에러, UI/UX |
| 리스트 | 데이터 로드, 빈 상태, 페이지네이션, UI/UX |
| CRUD | 조회/생성/수정/삭제, 권한, UI/UX |
| task | 기능 동작, 에러 상황, 기존 영향 없음 |
| bug | 재현 확인, 수정 후 정상, 회귀 없음 |

```bash
gh issue edit {number} --body "{updated_body}" --repo {repo}
```

---

## report — 마일스톤별 리포트

```bash
gh issue list --repo {repo} --milestone "{name}" --state all --json number,title,body,labels,state --limit 100
```

```
테스트 리포트 — {milestone}

| 페이지 | 전체 | 통과 | 진행률 | 상태 |
|--------|------|------|-------|------|
| 로그인 (#10) | 9 | 9 | 100% | ✅ |
| 체크리스트 (#20) | 12 | 8 | 67% | ⚠ |

리스크:
- {진행률 낮은 페이지 경고}
```

---

## 안전 장치

- 이슈 body 편집 실패 시 원본 보존
- 테스트 섹션 없는 이슈 → add 안내
- closed인데 미통과 → 경고
